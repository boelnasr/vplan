Blocked plans

A blocked plan is a planner round the Verifier rejected. Physical-constraint rejections are kept apart from solver non-convergence (IK accuracy and continuity: the IK solver did not converge or jumped branch, which is not proof that a pose is unreachable) and from malformed output, which never reaches the Verifier. A round with both kinds counts as solver non-convergence, because a solver failure stops the later segment checks. The heuristic is deterministic, so its rounds after the first repeat the same plan (D39).

Definitions and limits

  • First-try success: the round-1 plan passes the gate and the Judge reports success. Config 2 is round 1 of config 3, rescored as an attempt with no repair budget.
  • Success with repair: success within k = 3 repair rounds, over the same tasks and denominator.
  • Gains: paired differences on the same tasks; 95% interval by percentile bootstrap over tasks (10,000 resamples, seed 0). Proportions carry 95% Wilson intervals and their N.
  • Feasible success and impossible-task refusals are separate results, so the task mix cannot inflate the headline (D8).
  • Grasping is attachment-assisted, a simulation simplification (spec §2). The Judge is independent check logic on the same physics engine as the Verifier (spec §13). The checks are sample-based, not formal guarantees.
  • The frontier row (config 6) is an optional reference without the verifier; it is excluded from the headline. The Cosmos shadow study (config 4) is a separate pass over saved frames and never measures incremental success; it is not part of this report.
  • Headline sources are Nebius Token Factory runs only (spec §14). Any Nemotron configuration that ran on another provider is labelled "dry run, not a headline result", and a report is a headline report only if configs 2, 3 and 7 all come from complete runs on Token Factory over the held-out test seeds (spec §14): an incomplete or limited run (D33) and a run on the development seeds are never headline sources.
